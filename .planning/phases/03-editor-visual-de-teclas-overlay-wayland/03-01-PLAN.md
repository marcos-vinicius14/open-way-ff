# Plan 03-01: Overlay Wayland Layer Shell, Cairo Input Region, Alternância Híbrida e Status Pill

**As a** jogador competitivo de Free Fire no Linux,  
**I want to** ter um overlay transparente renderizado via Wayland Layer Shell sobre o Waydroid com pass-through total de cliques em jogo e banner superior discreto no mouse livre,  
**so that** a janela do emulador receba 100% dos cliques e eventos de teclado sem latência ou desvios de foco durante a partida.

<objective>
Implementar a janela de overlay fullscreen transparente (`WayFireOverlayWindow`) utilizando GTK4, Libadwaita e `gtk4-layer-shell` com fallback gracioso para janelas normais, controle dinâmico de `cairo.Region` para pass-through total em modo de jogo, alternância para tela interativa em modo de edição e o componente flutuante `StatusPill` exibindo o estado da mira (`F1`) e atalho de acesso ao editor (`F2`).

Purpose: Cumprir o requisito UI-01 e as decisões arquiteturais D-01, D-02, D-04 e D-12, estabelecendo a fundação gráfica transparente e de baixa latência sobre Wayland.
Output: Módulos `src/wayfire/ui/overlay.py`, `src/wayfire/ui/status_pill.py` e testes herméticos em `tests/test_overlay_window.py`.
</objective>

<threat_model>
### ASVS Level 1 Threat Assessment

1. **Threat — Input Hijacking / Focus Stealing (CWE-200, CWE-284):** Se o overlay GTK4 capturar foco de teclado ou bloquear cliques de mouse durante a partida, o jogador perderá controle sobre o jogo e o Waydroid sofrerá perda de foco.
   - *Mitigation:* Em Modo de Jogo, a superfície obrigatoriamente aplica `Gtk4LayerShell.set_keyboard_mode(window, Gtk4LayerShell.KeyboardMode.NONE)` e define a região de entrada como uma `cairo.Region()` vazia. Nenhuma entrada física é interceptada pelo overlay enquanto o jogo estiver em execução.
2. **Threat — DoS via Unsupported Compositor Crash (CWE-755):** A invocação cega de funções de `Gtk4LayerShell` em ambientes sem suporte ao protocolo `zwlr_layer_shell_v1` (ex: X11/Xvfb ou compositores incompletos) pode gerar falha de segmentação ou `g_error`.
   - *Mitigation:* Método seguro `_can_use_layer_shell()` checa disponibilidade de display Wayland e suporte do protocolo com blocos `try/except` defensivos, ativando automaticamente o modo de fallback fullscreen padrão sem quebrar a execução.
</threat_model>

         gi.require_version("Gtk", "4.0")
         gi.require_version("Adw", "1")
         try:
             gi.require_version("Gtk4LayerShell", "1.0")
             from gi.repository import Gtk4LayerShell
             HAS_LAYER_SHELL = True
         except (ValueError, ImportError):
             HAS_LAYER_SHELL = False

         - `__init__(self, app: Optional[Gtk.Application] = None, enable_layer_shell: bool = True)`:

           - Adiciona classe CSS `"wayfire-overlay-window"`.

           - Executa configuração Layer Shell no construtor antes de qualquer mapeamento/realização:
             Se `HAS_LAYER_SHELL and enable_layer_shell and self._can_use_layer_shell()`:
               `Gtk4LayerShell.init_for_window(self)`
               `Gtk4LayerShell.set_layer(self, Gtk4LayerShell.Layer.OVERLAY)`
               `Gtk4LayerShell.set_namespace(self, "wayfire-overlay")`
               `Gtk4LayerShell.set_exclusive_zone(self, -1)`
               Para cada borda (`TOP`, `BOTTOM`, `LEFT`, `RIGHT`): `Gtk4LayerShell.set_anchor(self, edge, True)`
               `Gtk4LayerShell.set_keyboard_mode(self, Gtk4LayerShell.KeyboardMode.NONE)`
               `self.is_layer_shell_active = True`
             Senão:
               Ativa fallback de janela fullscreen transparente (`self.fullscreen()`).
           - Conecta evento `"realize"` para chamar `self._apply_input_region()`.
         - Método `_can_use_layer_shell(self) -> bool`:
           Verifica se `Gdk.Display.get_default()` é válido e se `Gtk4LayerShell.is_supported()` retorna True (com captura de exceções).
         - Método `set_mode(self, mode: OverlayMode) -> None`:
           Atualiza `self.mode = mode` e reconfigura o teclado Layer Shell:
           Se `mode == OverlayMode.EDIT_MODE` e `self.is_layer_shell_active`:
             `Gtk4LayerShell.set_keyboard_mode(self, Gtk4LayerShell.KeyboardMode.ON_DEMAND)`
           Senão se `self.is_layer_shell_active`:
             `Gtk4LayerShell.set_keyboard_mode(self, Gtk4LayerShell.KeyboardMode.NONE)`
           Chama `self._apply_input_region()`.
         - Método `set_game_mode(self, suspended: bool = False, pill_rect: Optional[cairo.RectangleInt] = None) -> None`:
           Atualiza `self._pill_rect = pill_rect`.
           Se `suspended`: define `OverlayMode.GAME_SUSPENDED`.
           Senão: define `OverlayMode.GAME_LOCKED`.
           Chama `self.set_mode(...)`.
         - Método `set_edit_mode(self) -> None`:
           Chama `self.set_mode(OverlayMode.EDIT_MODE)`.
         - Método `toggle_edit_mode(self) -> OverlayMode`:
           Se `self.mode == OverlayMode.EDIT_MODE`, retorna para `GAME_LOCKED` (ou `GAME_SUSPENDED` se mouse suspenso). Senão, vai para `EDIT_MODE`.
         - Método `_apply_input_region(self) -> None`:
           Obtém a superfície gráfica via `self.get_surface()`. Se `surface is None`, retorna defensivamente.
           Se `self.mode == OverlayMode.GAME_LOCKED`:
             Cria `empty_region = cairo.Region()` e executa `surface.set_input_region(empty_region)` per D-01.
           Se `self.mode == OverlayMode.GAME_SUSPENDED`:
             Se `self._pill_rect` estiver definido: cria `pill_region = cairo.Region(self._pill_rect)` e aplica `surface.set_input_region(pill_region)` per D-01.
             Senão: aplica região vazia `cairo.Region()`.
           Se `self.mode == OverlayMode.EDIT_MODE`:
             Aplica `surface.set_input_region(None)` (tela cheia interativa) per D-01.
         - Método auxiliar `compute_input_region_description() -> str`:
           Retorna string descritiva (`"EMPTY"`, `"PILL_ONLY"`, `"FULLSCREEN"`) facilitando testes e depuração de estado.
    3. Criar `tests/test_overlay_window.py` contendo:

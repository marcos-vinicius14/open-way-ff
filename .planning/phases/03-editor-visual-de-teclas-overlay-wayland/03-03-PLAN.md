# Plan 03-03: Mapeamento Polimórfico de Widgets, Macros Sequenciais, Rótulos Canônicos/OSD, OSD HUD & Keymap Engine

**As a** jogador competitivo de Free Fire no Linux,  
**I want to** ter suporte completo a botões Tap, analógico WASD de 8 direções, Mira FPS, Gatilho de Tiro e Macros Sequenciais numerados, visualizados com estilo GG Mouse Pro translúcido, feedback de clique e controle de opacidade de 0% a 100%,  
**so that** meus comandos respondam com precisão instantânea (<1ms) e eu possa jogar com HUD customizado ou 100% invisível em partidas competitivas.

<threat_model>
### ASVS Level 1 Threat Assessment

1. **Threat — Denial of Service via Latency Injection / Blocking Input Loop (CWE-400 / CWE-703):** Se a reprodução de macros sequenciais utilizasse `time.sleep` na thread de entrada ou no loop de eventos, o processamento de novos movimentos de mouse pararia, violando o compromisso de latência <1ms e provocando travamento de câmera no Waydroid.
   - *Mitigation:* `NonBlockingMacroScheduler` enfileira eventos com carimbos de data/hora monotônicos (`time.monotonic()`) e executa a verificação no loop de polling sem qualquer chamada bloqueante de sleep.
2. **Threat — Resource Exhaustion via Multi-Touch Slot Collisions (CWE-400):** Macros rápidas ou teclas pressionadas simultaneamente poderiam esgotar os 10 slots disponíveis do kernel uinput, deixando toques fantasmas presos na tela do emulador.
   - *Mitigation:* Isolamento estrito de slots de toque: Slot 0 reservado para câmera (`AimEngine`), Slot 1 para gatilho (`FireWidget`), Slots 2–3 para toques dinâmicos/DPad, e Slots 4–9 alocados e reciclados dinamicamente com pulso de soltura obrigatório (15ms).
3. **Threat — Race Condition / Memory Corruption in GTK Loop (CWE-362):** Disparar atualizações visuais de widgets GTK (como adicionar classes CSS `.pressed`) a partir da thread de eventos do evdev corrompe o estado interno do GTK.
   - *Mitigation:* Todos os despachos de notificação de estado de teclas vindos de `KeymapEngine` para a interface utilizam estritamente `GLib.idle_add(callback, *args)`.
</threat_model>

       - Classe `NonBlockingMacroScheduler`:
         - `__init__(self, injector: TouchInjector, slot_start: int = 4, slot_end: int = 9)`:
           Armazena `self.injector = injector`, `self.available_slots = list(range(slot_start, slot_end + 1))`, e fila `self.queue: list[tuple[float, str, int, int, int]] = []` (onde cada item é `(fire_at, action, slot, x, y)`).
         - Método `trigger_macro(self, macro: MacroWidget) -> None`:
           Se `not self.available_slots or not macro.steps`, retorna.
           Aloca um slot de `self.available_slots.pop(0)`.
           Calcula tempos relativos usando `now = time.monotonic()` e `accumulated_delay = 0.0`.
           Para cada passo:
             `touch_down_time = now + accumulated_delay`
             `touch_up_time = touch_down_time + 0.015` (pulso de 15ms)
             Enfileira `(touch_down_time, "down", slot, int(step.x), int(step.y))`.
             Enfileira `(touch_up_time, "up", slot, int(step.x), int(step.y))`.
             Incrementa `accumulated_delay += (step.delay_ms or macro.delay_ms) / 1000.0`.
           Enfileira reciclagem do slot: `(now + accumulated_delay + 0.01, "release_slot", slot, 0, 0)`.
         - Método `process_scheduled(self) -> None`:
           Obtém `now = time.monotonic()`.
           Itera sobre `self.queue`, disparando ações prontas via `self.injector.touch_down` / `self.injector.touch_up` ou devolvendo o slot para `self.available_slots`. Mantém na fila os itens futuros.

- `src/wayfire/core/keymap_engine.py`: Motor de baixo nível de despacho de teclas físicas para toques uinput multitouch.
- `src/wayfire/ui/widget_views.py`: Componentes visuais dos botões, analógico WASD, área de mira e sequências de macro com estilo GG Mouse Pro.
- `src/wayfire/cli/main.py`: Integração do `KeymapEngine`, atalhos `F2`/`F3` e do overlay no comando de execução principal.
- `tests/test_key_codes.py`: Suíte de testes para conversores de teclas e regras de bloqueio.
- `tests/test_macro_widget.py`: Suíte de testes para serialização de macros e execução do scheduler.
- `tests/test_keymap_engine.py`: Suíte de testes para despacho de toques uinput e cálculo de DPad.
- `tests/test_widget_views.py`: Suíte de testes para estilo visual, opacidade OSD e animação de feedback.

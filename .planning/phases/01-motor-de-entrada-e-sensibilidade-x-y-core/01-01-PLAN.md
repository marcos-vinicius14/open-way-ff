# Plan 01-01: Dispositivo Virtual Multitouch (/dev/uinput) e Injetor de Toque

**As a** jogador competitivo de Free Fire no Linux,  
**I want to** ter um dispositivo touchscreen virtual multitouch Type B criado diretamente no Kernel Linux via `/dev/uinput`,  
**so that** o Waydroid e o compositor Wayland reconheçam toques nativos com latência instantânea (<1ms) sem intermediários lentos.

<objective>
Implementar a fundação do motor de entrada do WayFire: a estrutura modular do projeto Python (`src/wayfire`), a abstração de dispositivo virtual `/dev/uinput` via `python-evdev` utilizando o protocolo Multi-Touch Type B com `INPUT_PROP_DIRECT`, gerenciamento robusto de slots multitouch (0..9), e primitiva de reset atômico com pausa de 1ms.

Purpose: Atender ao requisito CORE-01 e decisões D-05, D-08 e D-15, viabilizando injeção de toques com latência imperceptível (<1ms) e fornecendo uma camada desacoplada de testes com mock para validação sem privilégios de root.
Output: Pacote Python configurado (`pyproject.toml`), módulo `src/wayfire/core/touch_injector.py`, fixtures de teste `tests/conftest.py`, e suíte de testes `tests/test_touch_injector.py`.
</objective>

           - `ecodes.EV_KEY: [ecodes.BTN_TOUCH]`
           - `ecodes.EV_ABS`: tuplas `AbsInfo` para `ABS_X` (min 0, max width), `ABS_Y` (min 0, max height), `ABS_MT_SLOT` (min 0, max 9), `ABS_MT_TRACKING_ID` (min 0, max 65535), `ABS_MT_POSITION_X` (min 0, max width), `ABS_MT_POSITION_Y` (min 0, max height).

           - Nome do dispositivo: `"WayFire Virtual Touchscreen"`.
         - Estado interno: `active_slots: set[int] = set()`, contador atômico de tracking ID `_next_tracking_id: int = 1` que incrementa e recicla entre 1 e 65535 via `_get_next_tracking_id()`.
         - Método `touch_down(slot: int, x: int, y: int) -> None`: adiciona `slot` a `active_slots`, obtém `tid`, escreve `ABS_MT_SLOT (slot)`, `ABS_MT_TRACKING_ID (tid)`, `ABS_MT_POSITION_X (x)`, `ABS_MT_POSITION_Y (y)`, `BTN_TOUCH (1)`, e chama `syn()`.
         - Método `touch_move(slot: int, x: int, y: int) -> None`: valida se slot está ativo; escreve `ABS_MT_SLOT (slot)`, `ABS_MT_POSITION_X (x)`, `ABS_MT_POSITION_Y (y)`, e chama `syn()`.
         - Método `touch_up(slot: int) -> None`: remove `slot` de `active_slots`, escreve `ABS_MT_SLOT (slot)`, `ABS_MT_TRACKING_ID (-1)`, escreve `BTN_TOUCH (1 se len(active_slots) > 0 senao 0)`, e chama `syn()`.
         - Método `close() -> None`: invoca `close()` no sink subjacente.
    4. Criar `tests/conftest.py` com fixture `mock_sink` retornando uma instância de `MockUInputSink`.

       - Definir constantes `MAX_SLOTS: int = 10` (slots válidos de 0 a 9) e `DYNAMIC_SLOT_RANGE: range = range(1, 10)`.
       - Implementar método `allocate_slot() -> int`: localiza o menor índice entre 1 e 9 que não esteja em `active_slots`; se todos ocupados, levanta `RuntimeError("No free multitouch slots available (1-9)")`.
       - Implementar método `release_slot(slot: int) -> None`: chama `touch_up(slot)` se o slot estiver ativo e remove-o do pool de alocação.
       - Implementar método `reset_slot_cycle(slot: int, anchor_x: int, anchor_y: int, pause_sec: float = 0.001) -> None` per D-05:

         2. Executa `time.sleep(pause_sec)` (pausa garantida de 1ms para processamento do `ACTION_UP` no subsistema de input Android).
         3. Executa `touch_down(slot, anchor_x, anchor_y)` (emite novo tracking ID positivo, novas coordenadas de âncora e `syn()`).
       - Adicionar validação e clamp de coordenadas nos métodos `touch_down` e `touch_move`: valores de `x` são limitados ao intervalo `[0, width]` e `y` ao intervalo `[0, height]`.

    2. Expandir a suíte de testes em `tests/test_touch_injector.py`:
       - `test_multislot_concurrent_touches`: ativa Slot 0 (câmera) e Slot 1 (botão de tiro), verifica que `BTN_TOUCH` é mantido em 1 quando Slot 0 é liberado enquanto Slot 1 continua ativo, e apenas transiciona para 0 quando Slot 1 também é liberado.
       - `test_slot_reservation_and_allocation`: garante que `allocate_slot()` nunca retorna o Slot 0 e aloca sequencialmente de 1 a 9, levantando `RuntimeError` ao esgotar.
       - `test_reset_slot_cycle_timing_and_events`: verifica que `reset_slot_cycle` emite evento de UP com tracking ID -1, aguarda pelo menos 1ms (medido via mock ou `perf_counter`), e emite novo DOWN com tracking ID diferente no ponto de âncora especificado.
       - `test_coordinate_clamping`: valida que tentativas de enviar coordenadas fora dos limites da tela (ex: x=-50 ou x=2500 para tela 1920x1080) são devidamente limitadas a [0, 1920] e [0, 1080].
       - `test_context_manager_cleanup`: verifica que sair do bloco `with TouchInjector(sink=...)` limpa todos os toques e fecha o sink.
